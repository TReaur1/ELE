# 实时协作协议（collab-relay）

> 版本 1.1。多 harness（ZCode / opencode / DSH / Trae）经 `collab/` 共享的实时协作协议。
> 接入方式：各 harness 的 MCP 配置注册 `python <repo>/collab/mcp_tools.py`（opencode 已在 `opencode.json` 注册）。
> v1.1：任务通道引入编排者-执行者模式，ZCode 任编排器，新增 review_task 与任务 role 字段。

---

## 一、通道总览

| 通道 | 工具 | 用途 | 实时性 |
|---|---|---|---|
| 消息 | post_message / get_messages | @定向或广播沟通 | 秒级（长轮询 25s） |
| 状态 | report_status / get_status_board | 在线/忙/阻塞看板 | 秒级 + 60s 心跳判离线 |
| 任务 | create_task / claim_task / complete_task / review_task / get_tasks | 任务分派、认领互斥与编排器验收 | 秒级 |
| git 代理 | git_push_proxy / git_sync | 代推送（解决推送通道阻塞）+ 同步广播 | 30s 轮询 |

---

## 二、消息协议

- 发送：`post_message(from, to, topic, body)`。`to` 填 agent 名（如 `DSH`）或 `ALL`（广播）。
- 拉取：`get_messages(to, since)`。`since` 用**上次返回的最新 seq**，首次用 0。
- **约定**：
  - `topic` 取值：`协作 / 状态 / 任务 / git / 审查 / 交接`。
  - 定向请求必须 @对方 agent 名；对方完成或答复后回 `ALL` 或定向。
  - 消息正文建议单条 ≤500 字；需交接代码时写清分支/提交/PR 编号。

## 三、状态协议

- 上报：`report_status(agent, state, task, role, note)`，每次调用刷新心跳（60s 内无上报自动判 `offline`）。
- `state` 取值：`idle`（空闲可接活）/ `busy`（忙）/ `blocked`（阻塞需协助）/ `done`（阶段完成）。
- 看板：`get_status_board()` 返回全部 agent（含 role/task/online）。
- **约定**：会话开始时注册（带 role）；每完成一个子任务更新一次；阻塞时 state=blocked 并附 note。

## 四、任务协议（v1.1 编排者-执行者）

生命周期：`open → claimed → done → review(approved 归档 / rejected 回 open 重做)`。

- 建：`create_task(title, detail, assignee, role)` → `{task_id}`。`role` 可选（生成/审查/测试），空=任意 agent 可认领。
- 认领：`claim_task(task_id, agent)` → `ok` 或 `already_claimed:<agent>`（**互斥**，防并发冲突）。
- 完成：`complete_task(task_id, agent, result)` → `ok`（须先认领）。
- 验收：`review_task(task_id, agent, approved, note)`（**编排器 ZCode 专用**）
  - `approved=true`：任务归档（state=done, review=approved）。
  - `approved=false`：**驳回**——任务回 `state=open`，`review=rejected`、`review_note` 附驳回原因；重新认领执行的提示词会自动带上驳回意见。
- **约定**：
  - 开工前必须认领成功；未认领不得完成；任务描述含"目标/范围/影响面/是否需 opencode 复核"。
  - `complete_task` ≠ 任务结束，**须经编排器 review 通过才算关闭**。
  - 编排器自身执行的任务由人工或其他 agent 交叉验收。
  - 编排器验收不替代 PR/CI 门禁，涉及 `main` 的合并仍走原有流程。

## 五、git 代理协议（解决 DSH 推送阻塞）

适用：harness 会话环境无法直连 GitHub（如 DSH 的 Connection reset）。

```
DSH: 本地提交完成 → git_push_proxy(agent, commit)
git_sync(本机): 轮询 /git/push_requests → 执行 git push origin main → 广播结果@ALL
```

- `git_push_proxy` 只记录请求；实际推送由 `collab/git_sync.py` 完成（须运行：`python collab/git_sync.py`）。
- 推送结果（成功/失败+输出）广播到消息通道 `topic=git`。
- 分支规则仍遵守 `skills/git-collab/SKILL.md`：只推 `feature/<agent名>/...` 分支，禁止直推 `main`（git_sync 默认推 main，若代理 feature 分支请人工确认）。

## 六、接入步骤（各 harness）

1. 启动 relay：`python collab/start_relay.py`（须常驻）。
2. 注册 MCP：
   ```json
   { "type": "local",
     "command": ["python", "<仓库>/collab/mcp_tools.py"],
     "environment": {"COLLAB_RELAY": "http://127.0.0.1:8790"} }
   ```
3. 会话开始时：`report_status(自己, idle, role=...)`；`get_messages(自己, 0)` 补拉离线消息。
4. 工作循环：拉消息 → 认领任务 → 执行 → 完成 → 上报状态。
5. 交接代码：本地提交 → `git_push_proxy`（或直推）→ 广播交接说明。

## 七、后台常驻响应（agent_daemon，推荐）

对话型 harness 在会话外无响应；`collab/agent_daemon.py` 补上后台常驻这一环：

```powershell
python collab/agent_daemon.py --mode notify   # 默认: 消息/任务落盘 inbox
python collab/agent_daemon.py --mode auto     # 进阶: 自动认领执行 open 任务
```

- **notify 模式（安全默认）**：轮询消息（`wait=0` 短轮询）+ open 任务 → 追加写 `collab/inbox_<agent>.md`。适合"先知情、人工/会话确认再处理"。
- **auto 模式**：消息仍 notify；**任务**自动 `claim → run-cmd 执行 → done + 广播`（认领互斥 + 一次一任务 + 超时，防重复与循环）。`--run-cmd` 可挂带 preset 的命令（如 DSH 的 headless+preset），以弥补"裸 headless 不懂 AGENTS/R1~R4"的硬伤；质量未确认前**默认不开 auto**。
- **角色过滤（v1.1）**：`--roles 生成,测试` 只认领匹配 role 的任务（role 为空的任务谁都可认领）；被编排器驳回的任务重做时，执行提示词自动附 `review_note` 驳回意见。
- 看板以 `<agent>-daemon` 名义心跳（**每 30s 周期上报**，relay 60s 判离线），可在 `get_status_board` 确认后台守护存活。
- 常用参数：`--agent`（收件名）、`--interval`（轮询秒，默认 3）、`--run-cmd`（auto 执行命令，默认 `opencode`，支持 `{}` 占位）、`--task-timeout`。
- 测试：`python collab/test_daemon.py`（notify 落盘 + auto 闭环 + 无僵尸进程回归）。

### 7.1 唤醒信号约定（跨 harness，2026-08-14）

三种触发信号统一约定，检测到即落 inbox 通知（DSH 与 opencode 共同确认）：
1. **消息 `topic=wake`** —— 紧急/需立即处理（发方明确指定接收者）。
2. **新建任务且 `assignee=<自己>`**（或未指定）—— 有活可接。
3. **状态看板出现 `blocked`** —— 对方求救，需要协助。

落地：agent_daemon 已满足 1/2（轮询消息+任务）；`blocked` 求救由各 harness 会话中 `get_status_board` 主动发现。

### 7.2 auto 执行 MCP 禁用约定（DSH 实测修复，2026-08-14）

- **问题**：`dsh --profile headless` 挂 electrical-assistant preset 时，5 个 MCP 行 spawn 的 node 子进程（Obsidian/cloud_brain/sequential_thinking 等）不随主进程退出，持有 daemon `subprocess.run(capture_output=True)` 的管道句柄 → 管道永不 EOF → auto 链路卡死到 task-timeout 兜底（任务 #3/#4/#5/#7/#8 均失败）。
- **修复**：electrical-assistant preset 所有 `mcp-*` 行加 `disabled: !!js process.env.DSH_HEADLESS_DISABLE_MCP === '1'`；启动 agent_daemon 前设环境变量 `DSH_HEADLESS_DISABLE_MCP=1`（daemon 及 spawn 的 headless 子进程继承）。
- **效果**：headless 不激活 MCP——手动实测 60s→26.5s、无子进程泄漏；端到端任务 #9 全链路成功（约 2.5min，含 agent 查证文件）。
- **第二道保险**：agent_daemon 超时后 taskkill /T 清理进程树（opencode 已实现）。
- **适用边界**：auto 无人值守任务不需要 MCP 外部工具；交互会话（Web）不受影响（不设该环境变量即可）。

## 八、局限与约定

- **准实时**：对话型 harness 在会话中主动调用；relay 常驻、通道随时可写。真正的后台自动响应需 harness 钩子（后续可选）。
- 消息**落盘**（SQLite `collab/collab.db`），重启不丢；但重要交接仍同步写 `CHANGELOG.md`（不依赖单点）。
- localhost 无鉴权；跨机部署需在 relay 加 token 校验。
- 状态看板以心跳为准：会话结束后 60s 自动离线，无需手动注销。
