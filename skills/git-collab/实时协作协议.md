# 实时协作协议（collab-relay）

> 版本 1.0。多 harness（opencode / DSH / Trae）经 `collab/` 共享的实时协作协议。
> 接入方式：各 harness 的 MCP 配置注册 `python <repo>/collab/mcp_tools.py`（opencode 已在 `opencode.json` 注册）。

---

## 一、通道总览

| 通道 | 工具 | 用途 | 实时性 |
|---|---|---|---|
| 消息 | post_message / get_messages | @定向或广播沟通 | 秒级（长轮询 25s） |
| 状态 | report_status / get_status_board | 在线/忙/阻塞看板 | 秒级 + 60s 心跳判离线 |
| 任务 | create_task / claim_task / complete_task / get_tasks | 任务分派与认领互斥 | 秒级 |
| git 代理 | git_push_proxy / git_sync | 代推送（解决推送通道阻塞）+ 同步广播 | 30s 轮询 |

---

## 二、消息协议

- 发送：`post_message(from, to, topic, body)`。`to` 填 agent 名（如 `DSH`）或 `ALL`（广播）。
- 拉取：`get_messages(to, since)`。`since` 用**上次返回的最新 seq**，首次用 0。
- **约定**：
  - `topic` 取值：`协作 / 状态 / 任务 / git / 审查 / 交接`。
  - 定向请求必须 @对方 agent 名；对方完成或答复后回 `ALL` 或定向。
  - 消息正文建议单条 ≤500 字；需交接代码时写清分支/提交/PR 编号。

## 三、状态协议

- 上报：`report_status(agent, state, task, role, note)`，每次调用刷新心跳（60s 内无上报自动判 `offline`）。
- `state` 取值：`idle`（空闲可接活）/ `busy`（忙）/ `blocked`（阻塞需协助）/ `done`（阶段完成）。
- 看板：`get_status_board()` 返回全部 agent（含 role/task/online）。
- **约定**：会话开始时注册（带 role）；每完成一个子任务更新一次；阻塞时 state=blocked 并附 note。

## 四、任务协议

生命周期：`open → claimed → done`。

- 建：`create_task(title, detail, assignee)` → `{task_id}`。
- 认领：`claim_task(task_id, agent)` → `ok` 或 `already_claimed:<agent>`（**互斥**，防并发冲突）。
- 完成：`complete_task(task_id, agent, result)` → `ok`（须先认领）。
- **约定**：开工前必须认领成功；未认领不得完成；任务描述含"目标/范围/影响面/是否需 opencode 复核"。

## 五、git 代理协议（解决 DSH 推送阻塞）

适用：harness 会话环境无法直连 GitHub（如 DSH 的 Connection reset）。

```
DSH: 本地提交完成 → git_push_proxy(agent, commit)
git_sync(本机): 轮询 /git/push_requests → 执行 git push origin main → 广播结果@ALL
```

- `git_push_proxy` 只记录请求；实际推送由 `collab/git_sync.py` 完成（须运行：`python collab/git_sync.py`）。
- 推送结果（成功/失败+输出）广播到消息通道 `topic=git`。
- 分支规则仍遵守 `skills/git-collab/SKILL.md`：只推 `feature/<agent名>/...` 分支，禁止直推 `main`（git_sync 默认推 main，若代理 feature 分支请人工确认）。

## 六、接入步骤（各 harness）

1. 启动 relay：`python collab/start_relay.py`（须常驻）。
2. 注册 MCP：
   ```json
   { "type": "local",
     "command": ["python", "<仓库>/collab/mcp_tools.py"],
     "environment": {"COLLAB_RELAY": "http://127.0.0.1:8790"} }
   ```
3. 会话开始时：`report_status(自己, idle, role=...)`；`get_messages(自己, 0)` 补拉离线消息。
4. 工作循环：拉消息 → 认领任务 → 执行 → 完成 → 上报状态。
5. 交接代码：本地提交 → `git_push_proxy`（或直推）→ 广播交接说明。

## 七、局限与约定

- **准实时**：对话型 harness 在会话中主动调用；relay 常驻、通道随时可写。真正的后台自动响应需 harness 钩子（后续可选）。
- 消息**落盘**（SQLite `collab/collab.db`），重启不丢；但重要交接仍同步写 `CHANGELOG.md`（不依赖单点）。
- localhost 无鉴权；跨机部署需在 relay 加 token 校验。
- 状态看板以心跳为准：会话结束后 60s 自动离线，无需手动注销。
